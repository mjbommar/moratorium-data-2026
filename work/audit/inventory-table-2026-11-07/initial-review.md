# Independent review of inventory table diff

Reviewed working-tree files at this point in time; implementation may continue changing. **Blockers remain.**

1. **The seven-column output is not readable in the supplied LaTeX wrapper.** `scripts/generate_tables/inventory_clean.py:110` uses seven unbounded `l` columns; the long footer lines also do not wrap. I ran `pdflatex -interaction=nonstopmode -halt-on-error` twice against `../compile-check.tex`, with all output in a temporary directory. Both passes exited successfully, but the second log reports overfull alignments up to 437.94 pt and still asks for another longtable width pass. `pdftotext -layout` of the resulting letter-size PDF shows the caption clipped and the first page cut off within the Sector column; Form and Status are outside the page. A zero exit code does not establish usable layout. Bound/wrap the table and notes, then verify a stabilized multi-pass PDF with all seven columns visible and legible.

2. **The range display implies a specific month that the canonical confidence flag does not establish.** `inventory_clean.py:69-71` turns every nonempty `range` value into its ISO year/month plus `?`, and the footer lumps range and unverified together. The CSV has five populated `range` records; for example Warrington Township (York County) records `2026-05-13` with range uncertainty, while its date field describes a March administrative pause and May ratification. Printing `2026-05?` discards the cross-month ambiguity and presents one month as the candidate adoption date. The CSV provides no structured range endpoints, so avoid representing a single month as the range; use an explicit range/uncertain marker without a date unless supported precision can be established from the canonical contract, and explain it in the table. Add a regression covering a range that crosses months, not only a same-month example.

3. **The artifact does not disclose material population and derivation caveats.** The caption calls this an inventory of moratoria, while the README states that the working inventory includes proposals, aggregate/compound records, and possible duplicates; recorded classifications do not establish current enforceability. The visible footer says only that classifications are recorded and not uniformly current. The actual selection excludes any jurisdiction whose name contains `federal`, `tva`, or `epa`, and Form and Sector are heuristic (Sector is capped at three); none of this is visible to a reader. The source line names broad source categories but omits the actual CSV and the visible snapshot does not explain the above limits. State the CSV source and selection and add concise caveats on proposals, unresolved grain/duplicates, recorded status versus legal force, and derived fields. The filter itself remains unchanged in `cleaned_inventory`.

4. **Regression coverage does not protect the population or compiled artifact.** The four current unit tests exercise meaningful normalized-date, status, and metadata cases, but use only a single mocked included row for `render`; they do not assert the unchanged substring filter, inclusion and sorting, consistency of the committed artifact with the renderer, or actual LaTeX page fit. Add focused population/artifact regressions and a practical compiled-layout check; ensure it catches the current clipping. The range test currently asserts the lossy behavior above.

Scope and evidence: I inspected the CSV codebook and date validator, current generator/common helper diff, generated table, README snapshot language, and the current test file. `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest tests.test_inventory_table` passed 4 tests on the inspected version; no broader suite was run. The generator reads dates solely from normalized fields and validates calendar values, and displays the recorded status without mining status prose, including a blank for a missing status. Current CSV status values are all populated; missing-status behavior is covered by a synthetic test. I did not verify underlying legal sources or source bodies, independently audit every table row, or evaluate future changes.
