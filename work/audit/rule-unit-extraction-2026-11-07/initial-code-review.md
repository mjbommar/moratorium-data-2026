## Blockers

1. **Non-finite backend accounting defeats the persistent stop.** `scripts/extract_rule_units.py:210-214,228-230` stores the invalid `cost_usd` in `attempt['accounting']` before checking it. For NaN or infinity, `save()` uses `allow_nan=False`, so the exception handler cannot serialize either the failure or `budget_stop`. The prior durable `reserved` attempt remains, but the next run dispatches again if the request/dollar caps leave room, contrary to the documented immediate stop for invalid cost. I reproduced two dispatches with `cost_usd=NaN` and a two-call cap. Normalize/reject non-JSON accounting values before assigning them and durably persist the stop; test NaN and both infinities, malformed accounting fields, restart, and zero additional calls. Also exercise storage-write failures after dispatch and specify reconciliation behavior when a durable stop cannot be written.

2. **The persistent accounting ledger is not integrity-checked or structurally validated.** At lines 174-182 and 201-205 only context and successful output/request hashes are checked; attempts, reservations, charges, statuses, stop flag, and their correspondence to successes are trusted. Accidental corruption such as deleting an attempt or changing its charge to zero can replenish the cap without an error, and unvalidated negative/non-finite values can change budget arithmetic. Hashes alongside data cannot authenticate malicious edits, but the stated fail-closed corruption requirement needs a durable integrity/consistency mechanism for the entire ledger and validation before any request, including known unit IDs, request hashes, statuses, finite nonnegative amounts, reserved values, unique success relationships, and budget stop. Test independent corruption/deletion of each category, interrupted reservations, and no dispatch after rejection; document the threat boundary for coordinated modification or rollback of all local files.

3. **Default storage can expose private source and outputs.** At lines 168-170 and `extract_document_resumable.py:25-39`, existing directories keep their existing permissions and default state/packet files are created using the process umask, potentially 0644; the lock similarly follows normal open semantics. The documented `PrivateRunStorage` is optional and its first use occurs after creating/opening the directory and lock. Sensitive text and model output may therefore be readable by other local users, and untrusted preexisting paths/symlinks are not guarded in the default path. Require an admitted private storage policy or enforce private directory/file modes and safe path handling before touching data; test permissive umask, existing public directories, symlinks, and storage boundaries. Do not place secrets in `settings` or `model_identity`: the entire values are persisted in the context, not redacted.

## Important correctness and coverage gaps

- The packet only carries `source_text_sha256` and caller-asserted `body_sha256`, with no document ID, title, URL or provenance, even if these are present in the document context (`packet`, lines 153-160). The plan binds exact extracted text, not document identity or original body. Identical text from different documents accepts the same plan; a syntactically valid body digest is not checked against bytes or proven to produce the text. Context prevents reuse after document metadata changes, but consumers of the standalone packet cannot recover document identity. Require or explicitly propagate stable caller-supplied document identity and provenance, make the text-to-body relationship an explicit externally verified assertion, and decide whether the plan must also bind document/body identity. Test same text with different IDs/bodies and changed-context preservation of both state and packet.
- A crash after a dispatch but before packet write can leave no packet or an older packet, despite the documentation's unconditional partial-packet language. A reserved attempt is durable, but replay does not materialize a packet until a later success/failure/cap; a persisted `budget_stop` raises before writing one. Either produce/rebuild a partial packet on entry and before a stop, or clearly specify when it is unavailable/stale. Test crash points after reservation, after response/state save, and before packet save; distinguish attempted, failed, reserved, and not attempted per unit. `attempted_units` currently counts a durable reservation even if dispatch never occurred.
- Existing tests cover output hash mutation only. Add pre-dispatch corruption tests for cached request hash, stored context/hash, source/plan and plan hash, cached unit IDs, malformed cached entries, and packet corruption. The packet is regenerated from state and its existing bytes are not validated; decide and document whether the packet is a disposable derivative or a retained artifact whose corruption must stop replay. Adjacent unkeyed hashes detect ordinary accidental mismatch, not coordinated edits.
- Add persistent dollar-cap tests with mixed successful charges, failures, an interrupted reservation, zero-cost success, cap exhaustion and restart; tests for invalid costs beyond the above, invalid/non-finite settings and reserved keyword arguments; explicit source-byte boundary including multibyte UTF-8, over-cap rejection before state/call, and full source in each dispatched prompt. Existing tests cover request cap with failed/cancelled calls, wrong IDs, unpriced/over-reservation/model mismatch, and basic changed context, but do not cover all these cases. Success on a different unit must not be accepted. Verify schema-invalid and ambiguous/unlocated quote flags remain non-accepted and inspect them during review.
- The prompt contains the entire untrusted source and caller-provided slot instruction in a single user message. Source instructions may influence the model; exact spans and typed output do not establish semantic entailment or neutralize prompt injection. Treat results as untrusted, retain independent review, constrain plan instructions operationally, and do not expose tools or secrets to the extraction backend. The backend may have configured toolsets and retry behavior; this adapter does not verify those settings or enforce HTTP-level limits. The supplied controlled transport and backend limits remain necessary for live use.

## Architecture and existing capabilities

The per-planned-unit prompt supplies the entire text, requests one typed clause or an explicit unresolved response, requires unique source-located anchors and matching unit IDs, and sets `accepted: false` and `review_required: true`. It bypasses the generic claim selector and its selection ceiling. It does not discover omitted units: completeness depends on the separately reviewed external plan, and an anchor alone does not prove a response addresses the intended unit. Invalid/ambiguous citations and strict-validator errors are flagged but still counted as candidates; humans must review the flags. No output is automatically accepted.

BC `CachingBackend` already provides typed result caching, model-aware keys, atomic cache writes and in-process same-key coalescing; malformed entries are cache misses and cached cost is reset to zero. BC batch provides bounded mapping, per-item outcomes and budget checks. Neither provides this workflow's cross-restart reservation ledger, immutable workspace binding, fail-closed hash checks, or end-to-end reconciliation as-is. Reuse/adapt these capabilities where appropriate, but do not substitute their cache-miss or in-memory meter semantics for the required durable controls. A wrapper cache also needs an explicit accounting policy so zero-cost replay does not conceal previously spent costs.
