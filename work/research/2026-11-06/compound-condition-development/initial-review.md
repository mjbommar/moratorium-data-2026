The main blockers are the native output schema and scoring of unknown expressions. This is a review of the in-progress files, not a claim that canonical integration is complete.

- **Native Structured Outputs needs a separate transport schema.** [condition_expression.py](/home/mjbommar/projects/personal/moratorium-data-2026/scripts/condition_expression.py:68) generates `allOf`/`if`/`then`, `uniqueItems`, and discriminated `oneOf` branches; the standalone schema also has an array root. The model extraction path embeds `ConditionClause` in [extract_domain_candidates.py](/home/mjbommar/projects/personal/moratorium-data-2026/scripts/extract_domain_candidates.py:113). OpenAI documents an object root, `anyOf`, and recursive schemas, but explicitly excludes `allOf`, `if`, and `then`; `uniqueItems` and `oneOf` are not in its documented supported subset. A strict request using this shape is therefore not established as supported. Generate a separate object-root native schema using supported recursive `anyOf` branches, and enforce uniqueness, cardinality, and other full constraints locally after parsing. [OpenAI Structured Outputs documentation](https://developers.openai.com/api/docs/guides/structured-outputs).

- **Unknown expressions can score as equivalent despite different content.** [condition_scoring.py](/home/mjbommar/projects/personal/moratorium-data-2026/scripts/condition_scoring.py:13) drops every `source_text`, including the sole content of an `unknown` node. Thus unknown “50 MW” and unknown “500 MW” normalize identically. Exclude the clause-level quotation only; retain unknown-node text, and add negative scoring tests.

- **Local semantic validation is coupled to whole-chunk parsing.** The recursive models enforce duplicate and count checks during Pydantic parsing, before the candidate-level error collection at [extract_domain_candidates.py](/home/mjbommar/projects/personal/moratorium-data-2026/scripts/extract_domain_candidates.py:209). One structurally valid native response with an invalid group can reject the entire chunk instead of retaining other candidates with an error. Use permissive transport models and validate each condition value separately; test nested invalid groups alongside valid facts.

- **Replay depends on mutable validator code.** Profile `1.0.3` pins the expanded schema, but [expanded_data.py](/home/mjbommar/projects/personal/moratorium-data-2026/scripts/expanded_data.py:80) also applies the current Python condition validator during historical checks. Later changes to that validator can invalidate an already sealed publication without changing its pinned schema. Make replay semantics versioned and pinned, or rely on the pinned schema for replay and explicitly version any additional semantic validator.

The current promotion and checker edits include explicit `1.0.3` downgrade checks and carry forward event-validity handling. I did not establish those paths end to end; add offline cases for same-table profile upgrades, exact replay, downgrade rejection, predecessor receipt changes, and withdrawn-event history.
