Useful inventory columns

The inventory CSV includes normalized fields alongside legacy descriptions. Useful fields include:

  • enacted_status — closed-vocab status: active, extended, replaced, expired, rescinded, pending, rejected, or unknown. The last two preserve rejected proposals and genuinely unresolved recorded stages separately. Filter to active + extended for records classified active or extended. These classifications do not prove freshly verified current legal force.
  • moratorium_id — stable identifier (<state>-<jurisdiction>-<year>, with phase suffixes for repeat instruments). Use this as a primary key when joining with future releases of this dataset.
  • current_end_date_iso — current fixed endpoint after any extension. Use it for expiry monitoring; duration_days preserves the original instrument's term.
  • latitude / longitude — WGS84 jurisdiction reference points. Census overrides use internal representative points, which are not necessarily geometric centroids. Drop the CSV into Mapbox, kepler.gl, Tableau, or any GIS tool to get an instant point map. 1326 of 1328 rows have coordinates; nonblank coordinates do not establish correct jurisdiction identity or legal applicability. See geocoding caveats.

Quick examples

Count records classified active or extended, by state (Excel): Open moratorium_inventory.csv, filter enacted_status to active and extended, then PivotTable on state.

Same in Python:

import pandas as pd
df = pd.read_csv("moratorium_inventory.csv")
in_force = df[df["enacted_status"].isin(["active", "extended"])]
print(in_force["state"].value_counts())

Filter to data-center-only moratoria (Python):

import json
df_dc = df[df["sectors"].map(lambda value: "data_center" in json.loads(value))]

Just the headline numbers (any tool): Read summary_stats.json. It has total counts, top-states list, and per-state aggregate stats including the enacted_status_breakdown field — useful for embedding live values in dashboards or articles.

A note on structured_extractions.jsonl

This file has 864 lines. 526 are successful structured extractions; 338 are LLM-call errors retained for transparency (so you can audit what didn't extract cleanly). The n=348 cohort referenced in the working paper is the subset with extraction.confidence >= 0.4.

import json
records = []
with open("structured_extractions.jsonl") as f:
    for line in f:
        r = json.loads(line)
        if r.get("error") is None and r["extraction"]["confidence"] >= 0.4:
            records.append(r)
assert len(records) == 348

A note on dates

Most date_enacted values are ISO format (YYYY-MM-DD). Some are YYYY-MM (day uncertain), YYYY (only year known), or include qualifying notes (reported, [VERIFY], proposed). When parsing programmatically, expect to handle both clean and messy values. The repository's examples/ directory has working code.

Reviewed ballot records

Canonical expanded records cover 57 reviewed proposal and measure records: 53 mapped frozen-cohort publications, Jay's solar ballot, Wilmington's litigated initiative, Bethel's town-meeting question, and an Augusta notice-only question with unresolved frozen-seed correspondence. There are 65 retained result versions and 53 current observations across 52 measures; five measures lack a current result. Three frozen candidate payloads remain held. Augusta's notice-only record may overlap one of them, so held payloads are not additional disjoint contests. Its sector and result/ordinance links remain unaccepted; see the gap dispositions and current accounting. Certification and legal implementation remain separate, record-specific findings. The generated results view supplies current record and observation counts; explicit supersession retains earlier observations. Unreported blank/turnout categories remain unknown. Operative dates and instrument links remain unresolved; electoral approval does not automatically increase in-force moratorium totals. This is a reviewed subset, not the full election census. See scope and interpretation and the publication protocol. The relative data/expanded pointer and its data/expanded-snapshots target must travel together.

Expanded CSV downloads

The current source generation selects validation profile 1.0.4. Separate retained, current-accepted and status event exports distinguish review state; none is a current-force timeline.

Instrument-event rows describe source-supported historical actions. An effective event does not establish current legal force; original expected endpoints do not prove actual expiry. See the event contract and profile for occurrence/observation time, evidence and unresolved-history distinctions.

The JSONL tables reached through data/expanded/ are authoritative for expanded records. These CSV files are derived from one pinned reviewed generation. They do not change the legacy moratorium denominator or establish new legal findings. measure_results.csv retains every observation; measure_results_current.csv excludes explicitly superseded observations while keeping separate county parts and other reporting scopes. It does not reduce a measure to a single result row.

Null or absent fields become empty cells, never inferred zeroes. Arrays and objects remain compact JSON within CSV cells. Use JSONL when distinguishing null, absent fields and empty strings or restoring exact typed records. Empty CSV tables have headers; their presence is not evidence that research coverage is complete.
